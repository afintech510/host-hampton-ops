## Root Cause: “No Tasks In Tasks Tab”

Symptom:
- Dashboard showed no tasks for review.
- API `GET /tasks` initially returned `{"tasks":[]}` even though HAMPTON logs showed tasks being created.

Cause:
- Supabase `task_status` enum on the deployed DB rejects `awaiting_approval`.
- HAMPTON code used `awaiting_approval` for DRAFT_AND_SHOW/ALWAYS_ASK holds and queried it in `/tasks`.
- This broke task listing queries and caused Tasks tab to appear empty.

Fix Applied (Backend):
- Represent “awaiting approval” as:
  - `status = 'pending'`
  - `approval_tier != 'AUTO_EXECUTE'`
  - `approved_at` and `rejected_at` are null
- Patched:
  - `services/hampton/src/approvalGate.ts`: write `pending` instead of `awaiting_approval`
  - `services/hampton/src/taskQueue.ts`: remove `awaiting_approval` from status filters
  - `services/hampton/src/types.ts`: remove `awaiting_approval` from union
- Deployed to VPS: rebuilt + restarted `hampton`.
- Verified live: `GET https://api.hosthampton.com/tasks` returns tasks again.

Fix Pending (Frontend):
- Dashboard code still filtered on `status === 'awaiting_approval'`.
- Patched locally to treat “needs approval” using the new derived logic:
  - `frontend/src/api.ts`: status union updated; added `approved_at`, `rejected_at`, `rejection_reason`
  - `frontend/src/App.tsx`: `needsAction` and `pendingApproval` computed from `pending + approval_tier != AUTO_EXECUTE + no approved_at/rejected_at`
- Requires Vercel redeploy of `app.hosthampton.com` to take effect.
